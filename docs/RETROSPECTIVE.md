## Keep — 잘한 것

- **코드보다 수용 기준을 먼저 적었다.** `CONTRACT.md`에 A1~A8 판정 방법과 목표를 먼저 두고, 데모 뒤에 실측을 대조했다. 특히 "승인 게이트 우회 경로가 코드에 존재하면 결함"이라는 한 줄이 약 2주 뒤 서버 측 우회(T6)를 결함으로 판정하는 기준이 됐다.
- **실패를 스키마 두 겹으로 분리했다.** LLM `json_schema`는 null을 허용하고 비즈니스 계약(zod)은 거부하게 해서, "LLM이 형식을 어겼다"와 "데이터가 계약을 어겼다"를 구분했다. 이 구조 덕분에 v1 실패가 순차 20/20, 동시 10/10으로 안정적으로 재현됐다(2026-09-28 재측정).
- **불리할 수 있는 실험을 사전 등록하고 돌렸다.** 진단 힌트 제거 실험(P3)은 성공 기준과 표본 수를 먼저 문서로 정했다. 결과(72% → 0%)는 README의 기존 주장을 약하게 만들었지만 그대로 첫 화면에 실었다.
- **보완은 재현 테스트부터 썼다.** PR #2의 결함마다 테스트를 먼저 쓰고 수정 전 코드에서 실패하는 것을 확인한 뒤 고쳤다. 테스트 0개에서 42개가 됐고, 독립 리뷰의 지적(MED-1·MED-2·LOW)도 같은 방식으로 반영했다.

## Problem — 아쉬운 것 (구체적 결과와 함께)

- **"자가진단"이라는 표현이 실제보다 컸다.** 진단 프롬프트에 정답 방향 예시가 있었고, 예시를 빼면 올바른 자가수정이 0/25였다. 힌트가 있어도 6/25는 연도를 2024년으로 바꿔 써서 2년으로 계산했다. 데모에서 본 4년은 72% 확률의 결과였다.
- **계약 통과를 정답으로 착각할 수 있는 구조였다.** 힌트 없는 조건에서 계약을 통과한 6회는 전부 "0년"이었다. zod 계약은 타입과 범위(0 이상)만 보므로 4년 경력자를 0년으로 기록해도 통과한다. 값의 타당성을 확인하는 장치는 사람의 승인뿐이다.
- **내가 정한 계약을 코드가 어겼다.** 승인 게이트가 화면 상태 전이로만 있었고, 서버는 받은 프롬프트를 그대로 실행했다(임의 프롬프트로 연차 99 주입 성공). 1차 수정 뒤에도 진단 입력을 위조하는 2차 우회가 리뷰에서 나왔다.
- **LLM에 들어가는 입력을 확인하지 않았다.** 자동 진단은 E2E 5/5에서 실제 오류 대신 기본 문구를 받고 있었다(stale closure). zod 오류 문구도 실제 값과 상관없이 "(null 수신)"으로 고정돼 있었다. 결과가 그럴듯해서 입력의 결함이 드러나지 않았다.
- **측정 스크립트를 남기지 않았다.** 2026-09-15 A2 10/10을 잰 스크립트는 세션 임시 폴더에 있다가 사라졌다. 첫 측정은 다른 앱에 붙어 거짓 10/10을 냈고, 당시 재측정으로 바로잡았지만 판정식은 여전히 `!r.ok`만 보는 구조였다. 2026-09-28 측정 스크립트도 아직 레포 밖에 있다.
- **이력이 한 번에 몰려 있다.** MVP 전체가 커밋 하나(+2,431줄)에 들어 있고, 당시 테스트·CI·PR은 0이었다. 약 18분짜리 단일 세션이라 작업 흐름을 이력으로 따라갈 수 없다.
- **배포와 A8(배포 환경 리허설 5연속)을 하지 못했다.** 배포본이 없고(추정 URL 404), A8은 `CONTRACT.md`에 미실시로 남아 있다. 로컬 E2E 5연속(5/5)이 대신한 값이다.
- **공개 레포에 로컬 AI 도구 상태(`.omc/`)가 커밋됐다.** 로컬 절대경로와 세션 ID가 들어 있었다(비밀키는 없음). 추적 해제는 PR #1로 올라가 있다.
- **README가 증빙을 앞질렀다.** 이전 README는 존재하지 않는 "리허설 기록"을 증빙으로 들었고, 배포하지 않았는데 "Vercel 배포"를 기술 구성에 적었다.
